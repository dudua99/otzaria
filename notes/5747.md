# Issue #5747 — bug notes (verify everything)
Type: BUG (milestone 0.9.99, from-app, Windows 0.9.98.3). Assignee: none. Maintainer stance: none (no comments). Reporter: in the app's text boxes (e.g. the app bug-report form, and "inside the text"), clicking at the END of a line to continue typing there puts the caret at the START of the next line; clicking mid-line works (video exists — do not open it; the text is enough).
Constraint: no visual change. Fix the caret placement only; keep #1716 (caret after Enter in RTL) and #3445 (visual arrows) working.

## Requested behavior
Clicking/tapping to the visual end (left side in RTL) of any line in a multi-line `RtlTextField` puts the caret at the end of THAT line; typing continues on that line.
Acceptance (reproduce FIRST — if the widget tests below pass on dev unchanged, report NOT READY with the evidence and the exact click offsets used):
- Hard break: text "שורה ראשונה\nשורה שניה", tap 20px to the left of the visual end of line 1 → clean `controller.selection` == collapsed(offset 11 = before '\n'), caret rect (`renderEditable.getLocalRectForCaret`) on line 1's y; typing "X" gives "שורה ראשונהX\nשורה שניה" (no new line created, no "\r" leaks into controller.text).
- Soft wrap: a long line wrapped in a narrow field (no '\n'), tap at the visual end of the first visual line → caret drawn on the first visual line (offset at the wrap with upstream affinity), not at the start of the second.
- Same with mixed Hebrew/Latin line ending in Latin.
- Mid-line click unchanged; Enter / arrows / undo unchanged (existing rtl_* tests green).

## Where in the code (upstream/dev @cee59520a)
- lib/widgets/text/rtl_text_field.dart: multi-line fields feed the TextField a raw copy with "\r\n" (`_setUpHardBreakWorkaround` L164, `_HardBreakController` L944); raw→clean sync `_syncCleanFromRawLive` L188, clean→raw `_syncRawFromCleanExternally` L222. Clicks are Flutter's default TextField gestures (no custom tap handling).
- lib/widgets/text/rtl_hard_break_workaround.dart: `snapOffsetOutOfCrlf` (offset between \r and \n → before \r) is applied only when collapsing raw→clean; the RAW controller keeps the in-between offset, so the caret is painted/edits are applied at raw offset "after \r" — candidate for "caret at start of next line" and for typing landing between \r and \n (then a lone \r is collapsed to a NEW line break: `collapseHardBreaks`).
- Users: app report form lib/app_report/view/app_report_dialog.dart (`app-report-title`, `app-report-description`), book error report, notes editor, etc. (`git grep -l "RtlTextField(" upstream/dev -- lib`, 32 files).

## Implementation sketch
- Snap the RAW selection too: when the raw controller gets a collapsed selection strictly between '\r' and '\n' (user tap), move it before '\r' with `TextAffinity.upstream` (one place: `_HardBreakController` value setter or `_syncCleanFromRawLive`), so paint and edits agree with the clean offset.
- For the soft-wrap case (if it reproduces): a tap that lands on a wrap offset whose caret rect is on the following visual line while the tap y is on the previous line → set `affinity: upstream`. Use `renderEditable.getLocalRectForCaret`/`getPositionForPoint`, no new gesture detector.
- Lean: reuse `snapOffsetOutOfCrlf`; no new widget.
