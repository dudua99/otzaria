## Requested behavior
In smart (semantic) search, when none of the results is the answer, the user can report "לא מצאתי" for the query, optionally pointing to the expected source (book + reference, or free text) when they find it later, so it can feed training.
Question: does the feedback service accept a new query-level event type, and what fields/limits? DEFAULT client design (behind a capability flag until the server is ready):
- Results screen footer/action "לא מצאתי את מה שחיפשתי" (ActionButton.ghost) → small dialog (catalog AppDialogFrame small): optional "מקור צפוי" (book picker or free text, ≤ limit) + optional note.
- Sends `_event(context, 'notFound', {expected: {...}|null, note})` via `SearchFeedbackEventBuilder` with the same query/scope/model context as votes; obeys existing consent gate and `SearchFeedbackLimits` truncation; offline queue like other feedback.
- Later "I found it": from an opened result or any reader line, "סמן כתשובה לשאילתה האחרונה" — OPTIONAL second step; skip in v1.
Acceptance (v1): action visible only when feedback consent is on; event payload validated by unit tests; no PII beyond what votes already send.
