# Issue #5758 — feature-default notes (verify everything)
Type: FEATURE (labelled bug by the app; from-app, Windows 0.9.98.3, report c80c15ea). Assignee: none. Maintainer stance: none (no comments). No open PR on this. Reporter: the "default distance between words" is one value for both regular (exact) and advanced search; wants a separate default per mode, like the word options (prefixes/suffixes) already are — exact: precise (0), advanced: flexible.
Constraint: no new UI surface; the existing "קבע את המרווח הנוכחי ({distance}) כברירת מחדל" item saves for the CURRENT mode. Fuzzy unchanged (its distance is edit distance).

## Requested behavior / DEFAULT
DEFAULT: distance default and session distance are kept per mode (exact / advanced), exactly like `_settingsKey` / `_exactSettingsKey` for the options.
- Save: the menu item saves to the current mode's key; snack text says which mode ("…כברירת מחדל לחיפוש הרגיל/המתקדם").
- New search: `initialDistanceForNewSearch(mode)` uses that mode's session value, else its saved default.
- Switching mode inside the new-search dialog: remember the old mode's distance to its session slot and load the new mode's distance (same place that swaps options).
- "Reset to defaults" in the dialog loads the current mode's saved distance.
- In-book search (`InBookSearchSettings.savedDefaults`) uses the saved default of the saved default mode.
- Migration: an existing `key-search-default-distance` value seeds BOTH per-mode keys on first read (users keep what they had); then the old key is no longer written.
Acceptance:
- Save 3 in advanced, 0 in exact → new advanced search opens with 3, new exact with 0 (fails on dev: both get the last saved).
- Dialog: exact (0) → switch to advanced → distance becomes advanced default 3 → back to exact → 0 (fails on dev).
- Old single key = 2, no per-mode keys → both modes open with 2.
- Fuzzy still opens with kMaxFuzzyDistance.
