# #6081 — portable install: the library location must be set again on every computer (triage 26.11)

Report (app report, Windows 11, 0.9.98+99803, bug): "כול פעם שמחברים למחשב אחר צריך מחדש לעשות את מקום הספרייה"
(portable install on a USB/external drive: each time it is plugged into another computer the library folder has to be chosen again).
No maintainer comment yet. Not assigned.

Hypothesis to VERIFY on dev first (do not assume):
- In portable mode the library path is stored as an absolute path (drive letter, e.g. E:\אוצריא\...). On another computer the
  drive letter changes, the stored path does not exist, and the app asks for the library again.
- Find how portable mode is detected (grep portable / isPortable / system_install.marker / app_paths) and where the library path
  setting is read/written (settings key for the library path, AppPaths). Check whether a relative-to-executable path is
  already supported.

Expected fix (only if the hypothesis holds): in portable mode, store the library path relative to the app folder when it is
on the same drive/inside the portable folder, and resolve it at startup against the current executable location; keep
absolute paths for non-portable installs and for libraries outside the portable folder. Migration: an existing absolute
path whose drive letter changed but whose relative part exists next to the executable resolves automatically.

Test: unit test of the path store/resolve function (portable root E:\P vs F:\P), plus the existing app_paths / settings tests.
Pitfalls: Windows-only paths in tests (use path package with windows style); do not change non-portable behaviour.
If portable mode does not exist on dev or the path is already relative -> NOT READY with evidence (and a question for the
reporter about how the portable copy was made).
