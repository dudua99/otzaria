# Issue #5840 — bug notes (verify everything)
Type: BUG (milestone 0.9.99, from-app, Windows 10, 0.9.98+99803). Assignee: none. Maintainer stance: none (no comments). No open PR on this. Reporter: when starting a new search, the previous query used to be selected on click/open so one keystroke replaced it; now the caret sits after the words and he must select + delete first ("it used to work").
Context: #4257 (closed, same build 0.9.98+99803) says the opposite for the REGULAR search — "the previous words are selected, typing replaces them" — and asked the same for semantic search; palmoni5 fixed semantic only in 5f7107d49 (06.11). So regular mode used to select; something now leaves the caret at the end.

## Reproduce first (mandatory)
Open the search dialog (Ctrl+Shift+F / "חיפוש חדש") with a restored last query (`SearchDialogQuery.loadLastTyping`) in: (1) regular mode, (2) advanced mode, (3) semantic mode, (4) edit-search from an existing search tab (`editTab` → `SearchingTab.clone`), (5) `existingTab` path. Record for each whether the whole query is selected right after open.
Widget tests must set `debugDefaultTargetPlatformOverride = TargetPlatform.windows` — Flutter's `EditableText.selectAllOnFocus` defaults to true only on desktop/web (`_defaultSelectAllOnFocus`, editable_text.dart; `_adjustedSelectionWhenFocused` skips select-all when `_nextFocusChangeIsInternal`/`_justResumed`/multiline). Under the default test platform (android) nothing is selected and the test proves nothing.
If every path already selects the whole query on dev → NOT READY with the table of results (and note that a mouse click INTO an already-focused field places the caret by design).

## Requested behavior
Opening a new search with a restored previous query always shows it fully selected (typing replaces it), in every mode, as semantic mode already does since 5f7107d49. Edit-search (`editTab`) keeps the same rule. Caret moves the user makes afterwards are not overridden.
Acceptance:
- Widget test (windows platform override): open SearchDialog with lastTyping "שבת" in regular and advanced mode → `queryController.selection == TextSelection(0, len)` after the post-frame focus; typing "x" leaves "x" (fails on dev if reproduced).
- Existing semantic tests in test/search/.../semantic_search_dialog_test.dart (from 5f7107d49) stay green.
