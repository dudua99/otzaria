# Issue #5599 — comprehensive alias matching for find-ref (follow-up on palmoni5's #5611 + #5620)

Forum thread (developers, 19–20.11): reporter shishko — "רשב"א בב" finds the book but "רשב"א בק" doesn't; users can't know whether to type "על"; same for whole sets ("פרוש המשניות" found only 3 tractates of "רמב"ם על ..."). The owner (dudua99) asked for a SERIOUS, COMPREHENSIVE solution covering all book kinds:
1. One central set of connector/filler words ("מילות קישור"), e.g. על, מסכת, מס', and similar (check the catalog for others: "ב" only as a separate word? "גמ'"? "פירוש"/"פי'"? "ספר"? — decide by DATA, not guesses), ignored on BOTH sides of the comparison, never cancelling a match.
2. Full/exact alias match still ranks FIRST; connector-stripped matches come after it (priority to the complete match).
3. Acronyms over part of the words (e.g. "יק"ש בראשית" should resolve like "ילקוט שמעוני בראשית") — verify how acronym matching works today and extend it generically if missing.
4. Cross-set alias unification: a commentator's set must be findable by its common collective names (e.g. "פירוש המשניות" / "פיה"מ" ↔ all "רמב"ם על <tractate>" books) — generic rule or a small central mapping in code, applied to external/attached DBs too (rules in code, not only in library data).
5. A proper central place in the code for these rules (a small, well-named module), not scattered special cases — refactor palmoni5's two special cases into it.
