# Issue #4274 — feature notes (verify everything)
Type: FEATURE (milestone 0.9.99). Assignee: none. Maintainer stance: none.

## Requested behavior
In the biographies tool (תולדות / ביוגרפיות), allow searching by a BOOK name: typing "חובות הלבבות" finds רבינו בחיי אבן פקודה.
Acceptance:
- `BiographiesRepository.filter` also matches the titles of each entry's `works` (BiographyWork.title), after the existing name/alias ranks: a name match always ranks above a work-title match.
- Ranking inside work matches mirrors names: exact < starts-with < whole-word < contains.
- Same normalization as names (`_normalize`, quote/geresh variants); the כהן/הכהן variant logic stays name-only.
- The card shows why it matched? Optional: no UI change required; nice-to-have = highlight the matching work (skip unless trivial).
- Plugin API that shares `filter` (doc comment: "Shared by the screen and the plugin API") returns the same order — document the change in the plugin SDK changelog if one exists.

## Where in the code
- lib/tools/biographies/repository/biographies_repository.dart `filter` (~L126-170): names = name + knownAs, `_matchRank` (exact<starts<whole<contains<variant), `_normalizedNames` Expando cache, `_noMatch`=5, `_titleVariantRank`=4.
- Model: lib/tools/biographies/models/biography.dart `BiographyWork { title, description }`, `Biography.works`.
- Screen: lib/tools/biographies/biographies_screen.dart `_performSearch` (~L122).

## Implementation sketch
- Cache normalized work titles in a second Expando.
- Compute `workRank = _matchRank(work, query, wholeWordPattern, null)`; final rank for work-only matches = `(_noMatch + workRank) * 2` placed in a third bucket after `variants`, or fold into `variants` with larger rank values — keep name matches strictly first.
- Keep perf: one pass, no per-keystroke allocations beyond today's.
