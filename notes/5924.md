# Issue #5924 — bug notes (verify everything)
Type: BUG (labelled bug; milestone 0.9.99, from-app, Windows 11, 0.9.98+99803). Assignee: none. No open PR. No comments.
Reporter: a search limited to a specific category/book is recorded in the history with an ID, so you cannot tell what the search scope was (screenshot not accessible from the container).

## Evidence (upstream/dev @3a612a22b)
- lib/history/view/history_screen.dart L427-463: subtitle `בקטגוריות: ...` built by `_facetDisplayNames(facets)` = last `/` segment of each facet.
- Book facets end with an opaque identity key: lib/search/book_facet.dart `buildFacetPath` L32-59 → `BookIdentity.fromParts` (lib/data/book_identity.dart L32-70) returns `id:<n>` / `uid:<n>` / `db:<slug>:<n>` / `ext:...` or `title|category|type|path`. So a search scoped to a book shows "בקטגוריות: id:1234" (or "שם|...|..." for legacy keys). Dimension facets (e.g. `/base`) show "base".
- The scope chip already solved this: lib/search/view/search_scope_menu.dart `_categoryFacetName` L436-453 — `ScopeTree.cachedFor(library)?.nodesByFacet[facet]?.title`, fallback strips `|...` and hides `id:/uid:/ext:` keys; `Category.displayNameForPathSegment` for categories.
- Same display data is used for the tooltip; search_history_menu.dart (title row) does not show scope, only history_screen.

## Suspected root cause
`_facetDisplayNames` predates ID-based book keys (moved in d6a630d3f; ID keys introduced around 46bc85221/4e90dfbab, centralised in e64e9fa24). Never updated.

## Fix direction
Resolve each facet to a display name: ScopeTree node title when the tree is cached (or build/lookup via DataRepository library — async; the history screen caches displays in `_searchDisplays`, so an async resolve must invalidate that cache and rebuild), else the `_categoryFacetName`-style fallback (title before `|`, `Category.displayNameForPathSegment`). Never show `id:`/`uid:`/`db:`/`ext:` raw; if unresolvable, show a neutral word (e.g. "ספר") or drop it. Consider sharing one helper with search_scope_menu instead of duplicating.

## Test idea
Extend test/history/view/history_search_display_test.dart: entry with `searchScopeFacets: ['/תנ"ך/תורה/id:5']` and a library/ScopeTree containing that book titled "בראשית" → subtitle `בקטגוריות: בראשית` (fails on dev: `id:5`). Unresolvable `id:9` → no raw key in subtitle/tooltip. Note L122 currently expects `bookKey:123` in the tooltip — update deliberately, explain in BODY.md.

## Tests to run
test/history/ (all), test/search/ scope menu tests, flutter analyze.

## Pitfalls
Do not change the stored facets or `searchHistoryKey` (backup merge identity). Keep the lazy display cache (d8832b2a8, perf). Categories with path segments that contain encoded chars must still go through `Category.displayNameForPathSegment`.
