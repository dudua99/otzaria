# Issue #4308 — feature notes (verify everything)
Type: FEATURE (milestone 0.9.99). Assignee: none. Maintainer stance: palmoni5 06.11: not a bug; `linker` in personal links is intentionally stored as commentary (used by the tool that generates link files for personal books, book+commentary pairs), anchors (`start`/`end`) are not kept; `reference` shows in text but opens the links window like official reference links. "קישור אישי מסוג 'ציטוט בתוך הטקסט', שיפתח את הספר ישירות, צריך דרך מפורשת לסמן אותו בקובץ (סוג או דגל חדש), כדי לא לשבור את קישורי המפרשים הקיימים. נשאיר את זה פתוח כבקשה לתוספת".

## Requested behavior
Personal link files should be able to create in-text citation links (anchored on `start`/`end`) that open the target book directly on click — like official linker links — without breaking existing `linker`→commentary behaviour.
Acceptance:
- New explicit marker in the import JSON: a new type label (e.g. `"type": "ציטוט"` / `"inline-link"`) OR a boolean flag `"inline": true` on a row. DEFAULT: new type value `INLINE_LINKER` (Hebrew label "ציטוט בטקסט") — explicit, discoverable in the docs, no ambiguity with existing `linker` files.
- Rows of that type keep `start`/`end` character anchors, are stored as the official linker connection type (so the reader renders them as in-text anchors and click opens the target directly), and are NOT converted to commentary and NOT flipped base↔commentary.
- Validation: start < end within the source line length; target line in range (existing checks); missing anchors → row error.
- Existing `linker`/`reference` files import exactly as before (regression tests).
- Docs for personal link files (where the import format is documented in the repo — grep docs/ for "קישורים אישיים"/user links) list the new type with an example.

## Where in the code
- Parser: lib/user_content_import/services/user_import_parser.dart `_connectionType` (~L616-625: LINKER → commentary), anchor label regex (~L628).
- Importer: lib/user_content_import/services/user_content_importer.dart ~L805-830 (linker→commentary normalisation, `flip` for dependent-text links), validation above it (~L795-812).
- Models: lib/user_content_import/models/user_import_models.dart `kNativeConnectionTypes` (L42-66), `kImportableConnectionTypes` (L71), Hebrew labels map (L77-97), `UserLinkRecord` (~L305-330) — check whether it already carries char offsets; if not, add nullable `startChar`/`endChar` columns to user_link (migration in lib/migration/database/daos/database.dart / user links table) — read how official linker anchors are stored (LinkQueries.sq).
- Rendering of linker anchors: lib/book_common/utils/link_anchor_markers.dart / database_library_provider.dart (user links merged into links).

## Implementation sketch
- Parser maps the new label to an internal `inlineLinker` marker; importer writes connection type `LINKER` with anchors, bypassing the commentary normalisation and flip.
- If schema change needed: additive nullable columns + migration test.
