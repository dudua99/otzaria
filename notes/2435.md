## Requested behavior
"Word-style" dark mode: the UI chrome is dark, but the book page stays black-on-white.
Acceptance:
- New persisted setting (Design tab, near theme mode): "דף הספר בהיר גם במצב כהה" (bool, default off). Only relevant when the effective brightness is dark (incl. system mode) — disabled/hidden otherwise.
- When on and dark: the reading surface (main text, commentary pane, page shape, continuous reading, personal-note previews inside the reader) uses the LIGHT reading palette: readerBackground, text colour, link colour (`AppSurfaces.readerLink`), selection colour, search/mark highlight roles (DD-17 light variants) — consistently; toolbars, side panels, tabs remain dark.
- PDF: no inversion filter and white page background, incl. page-turn animation.
- Toggling applies live without reopening books.

## Implementation sketch
- Cleanest: wrap the reading area in a `Theme(data: lightReadingTheme)` built from the light ColorScheme + light AppSurfaceColors when the option is on (one wrapper at the reader root and commentary pane root), so all role-based colours flip together without per-widget conditionals. Check that reader widgets read colours from Theme.of(context) (not from a cached global) — fix stragglers.
- PDF filter: condition on effective "page light" flag instead of brightness.
