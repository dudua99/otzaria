# 6022 — next/previous section with the arrows starts from the top of the screen, not from the selected section

## Summary
The reporter built from dev (~24.11). Arrow navigation in the reader now also selects the target section (#3708). But when a section is already selected in the middle of the screen, the first Left/Right press selects the section after the TOP visible line, so the selection jumps to the top of the screen instead of moving to the next section.

## Evidence
- `lib/text_book/view/text_book_screen.dart:1960-1980` `_scrollByLines`: `final current = widget.tab.index;` — `TextBookTab.index` is the scroll position (top source line, written only from `LineScrollController.position`, `lib/tabs/models/text_tab.dart:33`), not the selected section. Then `UpdateSelectedIndex(target)` + `scrollToLine(target, alignment: 0)`.
- Suspected root cause: 9c79c5f14 (palmoni5, 13.11, "עיון: מעבר לקטע הבא או הקודם בוחר אותו (#3708)") added `UpdateSelectedIndex(target)` but kept `current = tab.index`. Before it, nothing was selected, so starting from the scroll position was right.

## Fix idea (minimal)
Start from `state.selectedIndex` when there is a selected section (or at least when it is on screen); otherwise keep `widget.tab.index`. Keep "consecutive presses continue from the target before the scroll lands": `UpdateSelectedIndex` already updates selectedIndex immediately, so it covers that too — verify in the bloc.

## Test idea
Widget/bloc test in the style of `test/text_book/view/text_book_screen_actions_test.dart` or `test/shortcuts/reader_arrow_routing_test.dart`: book with 50 lines, scroll at line 0, select line 10, fire next-segment -> selectedIndex must be 11 (dev: 1). Same for previous -> 9. Also: no selection -> still from tab.index (no change).

## Pitfalls
- Do not break #5904 (2a2b78588, prev segment keeps selection in combined view) — run `test/text_book/view/combined_view/prev_segment_keeps_selection_test.dart`, `side_arrow_navigation_test.dart`.
- Multi-selection (Ctrl+click, `selectedIndices`): use `selectedIndex` only.
- Plugin reader path (`PluginTextReaderRegistry`) unchanged.
- Selected section that is far off screen (user scrolled away): decide — prefer continuing from the selection only if visible; say in BODY which was chosen.
