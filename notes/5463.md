# Issue #5463 — "copy with header on a separate line" ignored when copying from Chumash (sweep 26.11 part 3)
Type: bug. Checked on dev 4fe1973a4.

## Reporter (answered the bot)
- Pastes into OneNote; copies with right-click → "העתק".
- The book name appears on the SAME line (before/after as chosen) instead of a separate line.
- Only when copying from Chumash (בראשית); from Gemara the copy is as expected.

## Evidence (file:line on dev)
- Header formatting: lib/utils/text/copy_utils.dart:204-250 `formatTextWithHeaders` — separate_line_* joins header and text with "\n" (L244/L247).
- HTML for the clipboard: copy_utils.dart:257-273 `buildStyledHtml` — splits on "\n": every line but the last becomes a `<div>`, the last a `<span>`. OneNote shows separate lines only if the header ends up in its own block.
- Call sites: selection copy lib/text_book/view/selection/selected_text_copy.dart:222-235 (headers added to the plain text AND to `htmlContentToUse` from `resolveHtmlTextForSelection`), paragraph copy lib/text_book/utils/reader_paragraph_copy.dart:32-39, commentary copy lib/utils/ui/context_menu_utils.dart:457-485.
- What differs in Chumash is the HTML of the line (nikud/teamim spans, verse markers, possibly a block element or a leading/trailing newline inside the line HTML, or the Tanach display profile in `applyCopyPreferencesForClipboard`), which can glue the header to the text in the HTML flavor while the plain text is right. OneNote uses the HTML flavor.

## Reproduce first (in a test, no OneNote needed)
1. Take a real Bereshit line from the library. The DB is not reachable here, but raw.githubusercontent.com/Otzaria/otzaria-library is: find the Bereshit (תורה/בראשית) source file and copy 1-2 verses with their HTML exactly. Do the same for a Berakhot line.
2. Run `buildSelectedTextCopy` (copyWithHeaders 'book_name' / 'book_and_path', copyHeaderFormat 'separate_line_before' and 'separate_line_after') and then `CopyUtils.buildClipboardItem` / `buildStyledHtml`, for both lines. Compare: the header must be a separate `<div>` (or followed by a block break) in the HTML for both books.
3. If the Chumash HTML is wrong → fix where the header is joined (e.g. join with a block break in HTML when the text HTML starts/ends with an inline element, or normalize the line HTML before `buildStyledHtml`). If both are identical and correct → NOT READY with the two HTML outputs as evidence (then the difference is in OneNote, and the reporter should be asked which view of Bereshit was open: plain / page shape / combined with Targum).

## Test
Unit test in test/utils/text/copy_utils_test.dart (or selected_text_copy test) with the real Bereshit line: separate_line_before → html contains `<div …>{header}</div>` before the text, and plain text "header\ntext". Must fail on dev.
