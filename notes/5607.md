# Issue #5607 — feature notes (verify everything; confirm the mechanism first)
Type: BUG report treated as FEATURE-DEFAULT (milestone 0.9.99, from-app). Assignee: none. Maintainer stance: none (only bot questions 19.11).
Reporter answers (mail, 20.11): returning to the root folder is only possible via "רענון" (another issue), and after "רענון" the tile STAYS greyed; "זה קורה בכל קוביה"; "לא עוזר ללחוץ על מקום אחר המסך".

## Most likely mechanism (verify before coding)
The library preview panel is ON by default (settings_state.dart L253 `libraryShowPreview: true`). In that mode a single click on a folder tile does `SelectCategoryForPreview` and the tile renders `isSelected` (DD-06 `selectedRow`, i.e. "greyed"): library_browser.dart L2231-2270 `_withCategorySelection` → `isSelected = previewVisible && libState.previewCategory == category`. Refresh deliberately re-resolves `previewCategory` by path (library_bloc.dart ~L200-212), and nothing clears it on a click on empty space. So the selection persists forever.
If the grey turns out to be keyboard focus (AppCard focus) or pressed state instead → adapt the fix to that mechanism; if it cannot be reproduced → NOT READY with evidence.

## Requested behavior / DEFAULT
DEFAULT (Explorer-like): the previewed folder/book selection can be cleared by the user:
- Click/tap on empty space of the library grid/list (not on a tile) clears the preview selection (`previewCategory` and `previewBook`) and the preview panel returns to its empty state.
- Esc in the library browser (when no dialog/search field consumes it) clears it too (DD-08 spirit).
- Navigating into a folder and back keeps the selection on the folder you came from (unchanged, standard behavior); refresh keeps it (unchanged) — but now it can be cleared.
Acceptance:
- Select folder → tile selected; click empty area → no tile selected (fails on dev).
- Esc clears. Clicking another tile selects it (unchanged). Preview off → no change at all.

## Where in the code (upstream/dev)
