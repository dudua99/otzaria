# Issue #5271 — feature notes (verify everything)
Type: FEATURE — Plugin SDK (milestone 0.9.99). Assignee: dudua99. Maintainer stance: dudua99 19.11 code check: not supported; `_loadInverseSourceRows` is display logic (limits types via `LinkTypes.inverseQueryTypes`, rewrites `connectionType`) so it can't be reused as-is; requirements: incoming by target side incl. line ranges and source identity, original connectionType, filters + bounded window, existing calls unchanged by default; no post-hoc inversion, no scanning all books; unit tests for both directions, combined results, same-title books from different sources, ranges, back-compat.

## Requested behavior
Plugins (e.g. dictionary plugin propagating translations over Mesorat HaShas links) need links that point INTO a given book/line window, filterable by `connectionTypes` (esp. MESORAT_HASHAS).
Acceptance:
- `library.getLinks` (and `library.getRawLinks`) accept `direction: 'outgoing' | 'incoming' | 'both'`; default `'outgoing'` = today's output byte-for-byte.
- `incoming`: rows whose TARGET (book2 / line2 range) is the requested book and overlaps [startLine, endLine]; each item keeps original metadata: source book identity (id/uid/title/source), `sourceLine`, target line(s), original `connectionType` (not the inverted display type).
- Same validation as today: window ≤ `_pluginLinksMaxWindowLines`, `connectionTypes`, `targetTitles` / `targetTitlePrefixes` filters (for incoming, these filter the SOURCE side — document it), `includeAnchors` ignored or rejected for incoming (decide; document).
- `both` = outgoing ∪ incoming with a `direction` field on each item; stable order.
- Respects book-source identity (same title from different DBs/attached libraries).
- SDK docs + API catalog entry updated.
