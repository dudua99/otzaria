# Issue #5925 — bug notes (verify everything)
Type: BUG (labelled bug; milestone 0.9.99, from-app, Windows 11, 0.9.98+99803). Assignee: none. No open PR. No comments.
Reporter: when the app loses window focus, the text selection in the main reading view is now kept (fixed), but in the commentaries, links and page-shape (צורת הדף) views it is still cleared.

## Evidence (upstream/dev @3a612a22b)
- The fix for #1585 (33eae9ca0, 30.09) only touched the main view: lib/text_book/view/combined_view/combined_book_screen.dart L851 `_selectionAreaFocusNode = _KeepSelectionOnWindowBlurFocusNode()`, passed at L2119; class at L3468-3479 (suppresses notifyListeners when primaryFocus==rootScope while lifecycle is resumed).
- Not covered (plain/implicit FocusNode → SelectableRegion clears on blur):
  - commentary pane: lib/text_book/view/commentary_list_base.dart L2296 `SelectionArea(key: _selectionAreaKey, ...)` — no focusNode (links pane reuses the commentary list machinery; check selected_line_links_view.dart for its own SelectionArea too).
  - notes/commentary items: lib/text_book/view/commentary_list_items.dart L689 `SelectionArea(` — no focusNode.
  - page shape: lib/text_book/view/page_shape/simple_text_viewer.dart L3016 `SelectableRegion(focusNode: _selectionFocusNode)`, created L1103 as plain `FocusNode(debugLabel: 'SelectionAreaFocus')`.

## Fix direction
Move `_KeepSelectionOnWindowBlurFocusNode` to a shared file (e.g. lib/widgets/misc/) and use it in all reader SelectionAreas/SelectableRegions above (SelectionArea accepts `focusNode:`). Keep the existing behaviour: focusing another widget inside the app still clears.

## Test idea
Mirror test/text_book/view/selection/selection_after_jump_test.dart L266-300 ("מעבר לחלון אחר שומר את הבחירה": handleViewFocusChanged unfocused/focused, lifecycle resumed) for the commentary list and the page-shape SimpleTextViewer; each fails on dev (selection empty after unfocus). Plus: requesting focus on another in-app node still clears.

test/text_book/view/selection/, test/text_book/view/page_shape/, commentary list tests under test/text_book/view/, flutter analyze.

## Pitfalls
page_shape `_selectionFocusNode` is also used for keyboard handling (`_resolvedKeyboardFocusNode`, NavigationKeyTracker) — swapping the class must not change hasFocus semantics, only suppress the listener notification. Don't touch PDF.
