2. **Fix our own finding (posted on the PR 22.11):** `openSearchableBooks` deduplicates by `BookIdentity.keyOf`. A local PDF can borrow the text book's id (see the comment in `BookIdentity`), and indexing uses `indexedFilePath` for such a PDF. So a text book and its PDF open in two tabs collapse into one key, and one of the two searchable documents is dropped before the facets are built. Deduplicate by the same identity the index uses (what the facet will match), so both are kept. Test first: text + PDF open with the same `id` → both facets are in the selection (fails on the current branch head, passes after the fix). Also keep: the same text book open twice → one facet.
