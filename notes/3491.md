# Issue #3491 — bug notes (verify everything)
Type: BUG/performance (milestone 0.9.99). Assignee: none. Maintainer stance: Y-PLONI 03.11: wheel is forwarded to pdfrx with factor 1.0 (#3101 merged 25.10); unclear whether distance is small or rendering stalls → asked for details.
Reporter answer (mail, 19.11 10:33): "פתחתי גמ' עירובין הדף זז לאט כחצי עמוד בגלילה מהירה של משטח מגע במחשב נייד (לעתים עם קפיצה קלה)" → TOUCHPAD, fast two-finger swipe, PDF moves only ~half a page; no wheel.

## Likely root cause (verify)
On desktop the PDF claims precision-touchpad PointerPanZoom gestures itself (issue #969) and converts each pan delta 1:1 into a PointerScrollEvent; on pan END it only resets the axis lock — there is NO momentum/fling. A fast flick therefore moves exactly the finger distance (~half a page), while the text reader (a Scrollable) gets a ballistic fling from the PanZoom end velocity. Suspect commit: b3e7a1c5a (2026-08-24, palmoni5, "PDF: נעילת ציר חכמה לגלילת לוח מגע", #969) — before it the gesture went to pdfrx's InteractiveViewer, which may have applied inertia. Regression-first: check `git show b3e7a1c5a^:lib/pdf_book/view/pdf_book_screen.dart` and pdfrx's own pan-zoom handling to confirm "it used to fling".

## Requested behavior
Two-finger touchpad scrolling in a PDF should feel like the text reader: a fast swipe continues with momentum proportional to release velocity; slow drags stay 1:1; axis lock (#969) and Ctrl+pinch zoom keep working.
Acceptance:
- Fast pan (high release velocity) → document keeps moving after PanZoomEnd and decelerates (friction comparable to the text reader's ClampingScrollSimulation on Windows).
- Slow pan → no extra movement (velocity below fling threshold).
- New pointer down / new pan / wheel event cancels a running fling.
- Axis lock still applies to the fling direction; horizontal fling only when `canPanHorizontally`.

## Implementation sketch
- `onPanEnd(Velocity v)`; if |v| > kMinFlingVelocity, run a Ticker with `ClampingScrollSimulation` (or FrictionSimulation) per axis and feed per-frame deltas through the same path as `_handleTrackpadPanDelta` (so axis lock + pdfrx scrolling stay one path). Cancel on any new pointer/pan/scroll.
- DD-21 (reduced motion): fling is scroll physics, like the text reader's, not a UI animation — keep it; mention in BODY.
