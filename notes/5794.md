# Issue #5794 — feature-default notes (verify everything)
Type: FEATURE/UX (labelled suggestion; milestone 0.9.99, from-app, Windows 10, 0.9.98+99800). Assignee: none. Maintainer stance: none. No open PR on this.
Reporter: in a commentators tab (opened as a separate tab) the header does not say which daf/chapter the shown commentaries belong to; asks to show the current daf/chapter in the title.

## Requested behavior / DEFAULT
DEFAULT: the top-bar title of the commentators tab becomes "מפרשים על <ספר> · <מיקום>" where <מיקום> is the location of the line(s) currently shown, worded exactly like History/bookmarks for that line (same ref helper, e.g. "ברכות ה." / "פרק ב, משנה ז"); for PDF — the current heading (`sourceTab.currentTitle`) when known. It updates on every navigation (nav pane, arrows, Ctrl+click multi-select → location of the first selected line + "ועוד" is NOT needed; first line only). Long titles: the bar already has `titleMaxLines` and ellipsis — keep the book name intact and let the location be truncated first if the bar has a way; otherwise ellipsis at the end is acceptable.
The tab-strip label ('מפרשים | <ספר>') is unchanged; optionally add the location to its tooltip only.
Acceptance:
- Widget test: text commentators tab on a Mishna/Gemara book, navigate to another chapter → title contains the new location text (fails on dev: only the book name).
- PDF commentators tab: title contains the current heading when the source tab has one.
- No layout change of the bar (title stays in the same slot; DS text style).
