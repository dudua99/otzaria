# Issue #5853 — feature notes (verify everything)
Type: FEATURE (milestone 0.9.99), from the forum (https://otzaria.org/forum/post/49878). Assignee: none. Maintainer stance: none yet.

## Requested behavior
The reporter tried "both modes in the settings" and in both, closing the app inside a book reopens that book at the same position on the next launch. They want an option so that on launch the app opens the HOME screen (library/home), not the last book.

## Investigate first (upstream/dev)
- Find the startup/session-restore setting(s) the reporter means ("both modes"): grep settings for open-tabs restore / startup screen / session restore (e.g. lib/settings/**, lib/navigation/**, lib/tabs/**, main_window_screen startup reveal, workspaces/session restore, `_restoreOpenTabs` in backup_service is backup-only).
- If an existing setting already allows "start at home" and it is broken → treat as BUG (root cause + regression commit).
- If no such option exists → feature-default: add one choice to the EXISTING startup setting (not a new separate toggle if a choice list exists): "open the home screen" — tabs may still be restored in the background (keep the session) but the visible screen on launch is the home/library screen; the last book is one click away in its tab. Respect AGENTS startup-path rules (no new await before first frame).

## Tests
- Setting = home: after a simulated restart with a restored book tab, the visible screen is home; the tab still exists.
- Other modes unchanged.

Settings row before/after (light/dark), 360 + wide.
