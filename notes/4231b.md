Type: BUG in the merged feature. The first PR #5674 (dcc90078b) and the follow-up 916f0b254 are on dev.
Why this is different from prbody/4231-fix: that attempt was READY and was merged. This note is about a defect left in the merged code, which dudua99's own review of #5674 already pointed out ("`book.author?.trim() == author` מפספס ספר שמחברו מופיע בתוך שדה מרובה מחברים").

## Bug
For a book with more than one author, `Book.author` is the GROUP_CONCAT of all names joined with ", ".
- lib/migration/database/daos/book_dao.dart:136-158 (`selectBookAuthorsMap`, ORDER BY a.name) builds that string.
- lib/library/view/library_browser.dart:2831 passes the whole string to `_showAuthorBooks`.
- lib/library/bloc/library_bloc.dart:894 keeps only books whose author string is EXACTLY equal: `book.author?.trim() == author`.

Result:
(a) Clicking the author of a single-author book "X" misses every book that X wrote with someone else ("X, Y").
(b) Clicking "X, Y" lists only books with exactly that pair, so the issue's request "לעבור לכל ספרי המחבר" is not met.
Root commit: 1472ca6d0 (#4231, 20.11).

## Fix idea
- Bloc: compare per author name. Split `book.author` on ", " (the exact separator used by book_dao) and keep books where ANY name equals the clicked author. Precompute the split once per filter pass, not per comparison.
- UI: for a multi-author book, render one link per name (same link widget and tooltip "כל ספרי המחבר"), so the user chooses which author. A single-author book stays unchanged.
- Keep the filter chip text "מחבר: X" with the single name.

## Pitfalls
- An author name may itself contain ", ". First check the real catalog: count `author.name LIKE '%, %'` in seforim.db if a DB is available, or say in BODY that it was not checked. If such names exist, take the author list from the DB (`book_author`), not from the joined string. `Book` has only the string today, so this may need `authorsByBookId` as List<String>. Keep the change small.
- Attached/user books may have a free-text author (bookMeta['author']). Treat them the same way.
- PR #5624 / library_browser.dart is touched by many PRs: run merge-tree against open PRs.
