# 3975b — touchpad vertical scroll swallows the first ~20px of every gesture (TabSwipeDetector arena)

## Why a second attempt (prbody/3975-fix was NOT READY)
The first attempt found the mechanism but stopped because (1) it read the reporter's answer as contradictory and
(2) it wanted a maintainer decision. Re-reading the reporter's reply (25.11, via mail): "I scroll with two fingers on the
touchpad and sometimes with the arrows ... I only have a touchpad". That matches exactly the mechanism below (two-finger
trackpad = PointerPanZoom, which goes through the gesture arena). The mechanism code is unchanged since the attempt
(`git log 9f5de64aa..upstream/dev -- lib/tabs/` is empty). Scope is deliberately narrow: fix the lost delta for
touchpad vertical scroll over Flutter content; PR says **Refs #3975** (not Closes): plugin/WebView stalls and arrows are
not covered and may be environmental.

## Evidence (upstream/dev 4fe1973a4)
- `lib/tabs/view/tab_swipe_detector.dart:76-100` — `RawGestureDetector` around tab content registers
  `TabContentVerticalDragRecognizer` (trackpad+touch) and `TrackpadTabSwipeRecognizer` (horizontal, trackpad).
- `lib/tabs/utils/tab_content_vertical_drag_recognizer.dart:4-29` — vertical "sink" (added 19a966255 for #3048) joins the
  arena for trackpad too; for trackpad its accept distance is `computeHitSlop(trackpad)` (= kTouchSlop 18px).
- `lib/tabs/utils/trackpad_tab_swipe_recognizer.dart:24-40` — rejects only on pinch; does not reject when |dy|>|dx|.
- With 3 members (Scrollable's VerticalDrag + sink + trackpad horizontal) nobody wins before ~18-20px; the Scrollable
  (`DragStartBehavior.start`) never receives the pre-win delta. Without the detector the Scrollable is the only member and
  wins immediately.
- Evidence test from the first attempt: `git fetch origin prbody/3975-fix && git show FETCH_HEAD:evidence_tab_swipe_vertical_scroll_test.dart`
  — PanZoom vertical steps of 4px over a ListView: without detector `[4,8,...,32]`, with TabSwipeDetector `[0,0,0,0,0,4,8,12]`.
- Present since 52c60c068 (tab swipe, 10.6) + 19a966255 (sink) — before 0.9.98.

## Fix idea (option א of the first verdict, minimal)
1. `TrackpadTabSwipeRecognizer.handleEvent`: on the first PanZoomUpdate where `|pan.dy| > |pan.dx|` → `resolve(rejected)`
   (a vertical gesture is never a tab swipe).
2. `TabContentVerticalDragRecognizer`: for `PointerDeviceKind.trackpad` join the arena only when `contentIsWebView()`
   (override `isPointerPanZoomAllowed`/`addAllowedPointerPanZoom` to bail out otherwise). Touch behavior unchanged.
Result: over Flutter content the Scrollable is (effectively) alone and wins on the first update.
