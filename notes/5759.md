## What is actually happening (verified in engine 7.2.0 source, pub cache rust/src/api/search_engine.rs)
- The book filter IS applied in the query (facets), so the reporter's "it searches everything" is not true for the hits themselves.
- But term expansion of each query word (prefixes/suffixes/full spelling options) is budgeted by the summed `doc_freq` over the WHOLE index, independent of the facet filter: `SINGLE_WORD_POSTINGS_BUDGET` 8M (L4849), per phrase position `PHRASE_POSITION_POSTINGS_BUDGET` 20M / `PHRASE_POSITION_MAX_EXPANSIONS` 8192 (L4862-4868), `materialize_term_set` (L12930-12960 phrase path, L13202 single word). A very common short word (here likely `לה` / `יש` / `כל` with affix options) overflows → lowest-priority expansions are dropped → `truncated=true` → the banner. Dropped forms are dropped inside Niddah too, so the warning is technically correct but the advice "צמצמו את החיפוש" (and narrowing the scope) cannot help.
- Other `truncated` sources (group cap 50k, SECTION_COUNT_BUDGET) cannot fire with 4 results — confirm.
