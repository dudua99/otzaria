# Issue #5905 — feature-default notes (verify everything)
Report: opening a reference from איתור (find-ref / locate, e.g. pasting "משלי כד, כו" + Enter) scrolls to the place but nothing marks WHICH segment was the target, so the user cannot tell which verse was meant.
Maintainer decision (palmoni5, 23.11, verbatim): "יש להוסיף 'בחירה' רגילה, כלומר שיהיה את הפס הקטן בצד כמו אחרי לחיצה על הקטע". Reporter confirmed this is what he meant.
So: after opening a book from איתור at a specific segment, the target segment must become the SELECTED segment exactly as if the user clicked it (the same selection state: side bar marker, commentators follow it). Not a new highlight style.

Where to look: the find-ref / איתור open path (search for the איתור dialog / find_ref usage, the event that opens a book at index) and how a click selects a segment (UpdateSelectedIndex in TextBookBloc; see commit 9c79c5f14 which made prev/next segment navigation select the target — reuse that pattern). Check text books in both regular and combined/split views; PDF is out of scope unless the same path trivially applies.
Pitfalls: do not select when opening a book normally (no target); the selection must survive the initial scroll (see #5904 notes: _onScroll may clear selection on stale visibleIndices — if the new selection is cleared by that, report it, do not hack around it).
Tests: widget/bloc test: open from איתור at index N → state.selectedIndex == N (fails on dev); open book without target → no selection.
Body: Closes #5905; say it implements palmoni5's instruction.
