# #5983 — HebrewBooks download is lost when the dialog is closed (sweep 26.11)

Report: "אי אפשר לעשות שום דבר בתוכנה תוך כדי שמורידים ספר מהמאגר של היברובוקס (דרך הלינק של ההורדה) — כל נגיעה
מפסיקה את ההורדה". No maintainer comment.

Evidence on dev (4fe1973a4), lib/library/view/otzar_book_dialog.dart:
- The dialog is opened with plain `showDialog` (lib/library/view/library_browser.dart:3349) -> barrierDismissible
  defaults to true: any click outside closes it. The download button (_HebrewBookDownloadButtonState._download,
  L239-327) is the only way to keep working, and the code intends the download to survive a close
  (L243 comment from ad209e94e: "ההורדה ממשיכה גם אם הדיאלוג נסגר באמצע").
- Without a configured HebrewBooks folder (key-hebrew-books-path empty = default), the bytes come from
  `service.download` (L275), `saveToConfiguredFolder` returns null, and then L289 `if (!mounted) return;`
  (from 416efe7e7, 02.09, safer-mode work) returns BEFORE `saveFileWithExtension` (L291). The finished download is
  silently discarded: no save dialog, no snack. That is "every touch stops the download".
- `saveFileWithExtension` (lib/utils/file/save_file_with_extension.dart:18-27) already accepts `context: null` and
  falls back to `navigatorKey.currentContext`, so the save can still be offered after the dialog closed.
- With a configured folder the download already continues and is saved (downloadToFolder L268) — reporter likely
  has no folder configured.

Fix (minimal, ~3 lines): when `!mounted` and `result != null`, still call `saveFileWithExtension(..., context: null)`
(navigatorKey fallback) and show the snack via UiSnack (global), instead of returning. Keep the mounted guard only
for setState. Do NOT make the dialog non-dismissible (that would block the app, opposite of the request).

Test idea: extend test/library/view/hebrew_book_download_test.dart (already uses http.runWithClient + MockClient and a
navigatorKey in `_wrap`): no folder configured, MockClient returns a small PDF after a delay; tap 'הורדת הקובץ',
close the dialog (Navigator.pop / tap barrier) before the response, complete the response -> expect the save path
to be requested (fake file_picker / save hook) or the success/cancel snack, and NOT silent. Must fail on dev.
Pitfalls: verifySaferModePassword is called inside saveFileWithExtension with the navigator context — keep it;
file_picker on desktop needs a platform fake in tests (see how other tests fake saveFileWithExtension).
Tests to run: test/library/view/hebrew_book_download_test.dart, test/library/services/hebrew_books_download_service_test.dart,
flutter analyze, dart format.
