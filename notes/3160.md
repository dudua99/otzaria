## Requested behavior
Users don't know plugins can add components (toolbar buttons, context-menu items); suggestion: enable "הוספת רכיבים לתוכנה" by default, explain it better, and group plugin actions under one "תוספים לספר" entry in the toolbar and context menu.
Question: (1) flip the default of the components permission to ON for NEW installs? (2) group plugin toolbar/context items under "תוספים לספר"?
DEFAULT: (1) keep OFF by default but improve the install-screen explanation with an explicit example ("לחיצה ימנית על טקסט בספר תציג ..."), (2) group: when ≥2 plugins contribute to the same surface, show one "תוספים" entry (submenu/overflow) — single contributor stays inline.
Acceptance (default):
- Install/permission screen text includes a concrete example; strings via settingsText + arb.
- Toolbar: plugin buttons beyond the first collapse into one "תוספים לספר" overflow button (catalog AppMenu); context menu: plugin items under a "תוספים" submenu when ≥2 plugins contribute; filters by book/selection preserved.
- Existing users' permission decisions untouched.
