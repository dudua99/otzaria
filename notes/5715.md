# Issue #5715 — bug notes (verify everything)
Type: BUG (milestone 0.9.99, from-app, Windows 0.9.98.3). Assignee: none. Maintainer stance: none (no comments). No open PR. Reporter: book "שמירת שבת כהלכתה", commentary panel → "פתח כרטיסיית מפרשים", searched "בתוך ההערות": the panel says "אין תוצאות" although the matches are highlighted in red.
Constraint: no visual change except the count/snippets now being correct.

## Requested behavior
In the commentators tab, a search whose matches are in the virtual "הערות" group (the book's inline/DB notes shown above the commentaries) is counted: the count, "תוצאה X מתוך N", prev/next and snippets include note matches; "אין תוצאות" only when nothing is highlighted anywhere.
Acceptance:
- Section whose notes contain "שבת" and whose commentaries don't → search "שבת" in the commentators-tab search → count = number of highlighted note matches, no "אין תוצאות" (fails on dev: total 0).
- Notes + commentaries both match → total = notes + commentaries; order = notes first (they are rendered above), then commentaries.
- Next/prev reach note matches (scroll the notes box to the match; at minimum bring the note into view) and continue into the commentaries.
- Snippet list includes note snippets (label "הערות"); tapping one goes to the note.
- Count for notes uses the SAME matching as their highlight (`_NotesCommentaryWidget._renderSettings`: partial-word when the query comes from the commentary field; book search parameters when the query equals the book searchText).

## Implementation sketch
- Let the search request carry the notes as leading pseudo-entries (e.g. `CommentarySearchRequested(..., extraEntries: [(key: 'notes:<line>:<i>', content: body)])` or a notes list) so `_compute` counts/snippets them with the same function; keep generation/flush logic unchanged. Recompute when the notes set changes (new section) — same trigger points as `_orderedLinks`.
- Navigation: global index < notesTotal → target the notes widget (GlobalKey on `_NotesCommentaryWidget`, `Scrollable.ensureVisible` / `commentarySearchMatchTarget` on its body); otherwise subtract and use the existing link offsets.
- Matching parity: pass the same partial/whole-word decision as `_renderSettings` (when `_bookSearchState` != null use `literalPartialWordMatch(query, wholeWord: book.searchWholeWord)`).
- Keep it lean; reuse helpers; no new UI.
