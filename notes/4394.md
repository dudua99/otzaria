# Issue #4394 — feature notes (verify everything)
Type: FEATURE/design (milestone 0.9.99). Assignee: none. Maintainer stance: none on this issue; related design rationale by Y-PLONI on #4016 (marker variants are deliberately distinct: brackets/bold/italic/Rashi script). NEEDS_DECISION.

## Requested behavior
Commentary marker letters should look like the printed source: e.g. באר הגולה's markers are shown as "[א]" in Rashi script, but in print they are small superscript letters in regular font without brackets ("וכן שאר האותיות").
Question: replace the synthetic variant system (which distinguishes commentators on one page) with print-like superscript letters, or offer it as an option?
DEFAULT (least disruptive): a display option "ציוני מפרשים כבדפוס" (superscript, regular font, no brackets) in the existing text-display patch system — off by default — applied per scope (book/category/global). When on, ALL markers render as superscript small letters; commentator differentiation is lost by the user's choice.
Acceptance (default):
- Option off: unchanged.
- Option on: marker letter rendered `<sup>`-style (scale kLinkAnchorMarkerScale, baseline raised), regular font (no Rashi/bold/italic/underline), no delimiters — in both render paths (HtmlWidget CSS and continuous TextStyle); copy behaviour unchanged (markers still governed by "ציוני המפרשים" show/hide).
- Hover/tap on the marker still opens the commentary.

## Where in the code
- lib/book_common/utils/link_anchor_variants.dart (variants; delimiter is written INTO the HTML text by `wrapLinkAnchorLetter` — the plain variant must skip wrapping), lib/book_common/utils/link_anchor_markers.dart (insertion, style index by book).
- Text-display patch plumbing (mirror `anchorMarkers`): lib/shortcuts/dynamic/dynamic_shortcut.dart, lib/settings/tabs/text_display_settings_section.dart, lib/text_book/bloc/text_book_bloc.dart ~L1490.

## Implementation sketch
- New patch field `anchorMarkerStyle { variants, print }`; marker insertion picks `print` → letter without delimiters + class `link-anchor-print`; renderers map it to superscript.
- Strings via settingsText + arb.
