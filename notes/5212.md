# Issue #5212 — numpad arrows / Home / End (NumLock off) do nothing in the reader (sweep 26.11 part 3)
Type: bug (Windows). Checked on dev 4fe1973a4. No maintainer comment; no question asked.

## Report
Arrow Up/Down, Home and End work on the main keys but not on the numeric keypad (NumLock off, the usual way of using the keypad as arrows).

## Cause (verify first — this is the key point)
- Flutter's Windows embedder resolves numpad keys by scan code (`scanCodeToLogicalMap_` in keyboard_key_embedder_handler.cc / key_mapping.g.cc). With NumLock off the keypad's 8 key is reported as logical `numpad8` (no character), not `arrowUp`; same for 2/7/1/9/3 (down/home/end/pageUp/pageDown). Confirm against the engine source of the Flutter version in pubspec/.fvmrc (or a Flutter issue) before coding; if Flutter does report arrowUp, close as NOT READY with that evidence.
- App handlers compare logical keys only:
  - lib/widgets/misc/progressive_scrolling.dart:314-338 (pageDown / arrowDown / arrowUp)
  - lib/text_book/view/text_book_screen.dart:2627-2631 (arrows), 2984 / 2995 (home / end)
  - lib/shortcuts/key_map.dart:75-82 (configurable shortcut names)
  - lib/shortcuts/keyboard_shortcuts.dart:233-241 maps numpad1..9 to digits (tab switching): with NumLock off this must NOT fire as a digit.
  So keypad navigation never matches.

## Fix idea
One shared helper, e.g. `lib/shortcuts/numpad_navigation.dart`:
`LogicalKeyboardKey navigationKeyOf(KeyEvent e)` → when `e.character == null` (NumLock off) map numpad8→arrowUp, numpad2→arrowDown, numpad4→arrowLeft, numpad6→arrowRight, numpad7→home, numpad1→end, numpad9→pageUp, numpad3→pageDown, numpad0→insert, numpadDecimal→delete; otherwise return e.logicalKey. Use it in the handlers above instead of `event.logicalKey` (and in the digit map, skip numpad digits without a character). Do not touch text fields (Flutter's EditableText has its own handling).

## Test (must fail on dev)
Widget test on the progressive-scrolling reader: `simulateKeyDownEvent(LogicalKeyboardKey.numpad2, physicalKey: PhysicalKeyboardKey.numpad2, character: null)` → the scroll offset moves like arrowDown; `numpad1` → jumps to the end like End. Plus a unit test for the helper: numpad8 with character '8' stays numpad8.

## Pitfalls
- `simulateKeyDownEvent` may synthesize a character for numpad keys: pass `character: null` explicitly / use `KeyEventSimulator` with platform 'windows' and check what it produces.
- Keep Ctrl+numpad digit tab shortcuts working with NumLock on.
