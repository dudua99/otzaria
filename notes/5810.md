## What dev does today (verified in code)
- Side pane of a text book: a user change dispatches `UpdateCommentators(isUserAction: true)` → `_saveActiveCommentatorsPerBook` (text_book_bloc.dart L1386-1393, L3622-3638) → restored on next open of that book. So per-book memory already exists for the side pane.
- Commentators tab: the selection lives only on the tab object (`CommentatorsTab.selectedCommentators`, saved in the session JSON). A NEW commentators tab starts from the source book's `activeCommentators` (commentators_tab.dart L64-69), i.e. the side-pane/default set. A change inside the tab (`_updateSelectedCommentators`, commentators_tab_screen.dart L1014-1017) is never persisted per book → the next commentators tab of the same book starts from the default again. This matches the report.

## Requested behavior / DEFAULT
DEFAULT: the commentators-tab selection is remembered PER BOOK, separately from the side pane: a user change in a commentators tab saves it (new per-book field, e.g. `commentatorsTabSelection` in `TextBookPerBookSettings`); a new commentators tab of that book starts from it when present, else from the source book's active commentators (today's behavior). "הצג הכל" is saved as the explicit full list resolved at save time — DECIDE in code: if a "select all" flag is cheap, store "all" so new commentators added later are included; otherwise the list.
The side pane's own per-book selection is not changed by the tab, and vice versa. "שמירת ברירת מחדל לקטגוריה" (`onCategoryDefaultsSaved` → `clearActiveCommentators`, L1188) also clears the tab field for that book.
PDF commentators tab: same rule if it has the same gap (check `PdfCommentatorsTab` / pdf_commentators_tab_screen.dart `_applyDefaultCommentatorsIfNeeded` L549) — otherwise say in BODY.
Acceptance:
- Widget/unit test: open commentators tab for book X → select all → dispose → open a new commentators tab for X → all selected (fails on dev).
- Book X side pane selection unchanged by the above; book Y unaffected.
- Session restore of an existing commentators tab still uses its own saved `selectedCommentators` (existing tests green).
