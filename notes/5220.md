# Issue #5220 — bug notes (verify everything)
Type: BUG (milestone 0.9.99). Assignee: none. Reporter mmichaelush (found via a test running a links file through the import code, dev@36dad5b). Maintainer stance: palmoni5 16.11: "צריך לבדוק אם זה זול. אם יש פה חישוב כבד אני לא רואה בזה צורך כ"כ" → CONDITIONAL: implement only with a cheap path and report the measured cost in BODY.

## Requested behavior
A personal-folder book is registered with `totalLines = 0`, so the bounds check in link import is skipped: a native link to line 40 of a 2-line personal book is stored as a dead link, silently.
Acceptance:
- Importing a native links file whose source/target is a personal textual book (txt/docx/html… from a custom folder) with a line index beyond the book's real line count → error row like the official-book case ('"<title>" (N שורות)'), link not stored.
- Valid indexes import as before. PDF personal books: unchanged (no line bounds; keep skipping).
- Cost measured: time per referenced personal book and per import run (with the per-title cache), stated in BODY.

## Where in the code (upstream/dev)
- lib/user_content_import/services/user_content_importer.dart L705-760 `_ingestNativeLinks` → `locate()` (uses `found.totalLines`, L759); bounds checks L800-838 guarded by `totalLines > 0`.
- lib/user_content_import/services/user_link_ref_resolver.dart L107-113 typedef `LocatedUserLinkBook` (title, isUserBook, categoryId, totalLines, isDependentOnly — no filePath), L116-122 locator.
- Why 0: lib/migration/database/repository/seforim_repository.dart L1067-1110 `insertExternalContentBook` inserts totalLines `0` (arg at ~L1094); L1128-1147 `replaceExternalBookToc` resets it to 0.
- ⚠ DO NOT store the count in `book.totalLines`: readers treat `totalLines > 0` as "content lives in DB `line` rows" — sqlite_data_provider.dart L396 / L436, database_library_provider.dart L3203-3213 `_readBookTextFromUserBooksDb` (`totalLines <= 0 → null` → falls back to the file). Setting it would make readers fetch empty DB lines. (This is why the reporter's suggestion "save the count at scan time" must not be done literally.)
- Cheapness evidence: lib/migration/services/external_book_import.dart L35-55 `PreparedExternalBook.prepare` already converts the WHOLE document (`convertDocumentFile`) to build the TOC at scan time; the reader gets external text via database_library_provider.dart `getBookText` L3072+ (find the exact line-splitting used for external files and reuse it, so counts match reader indexes).

## Implementation sketch (default)
- Lazily, only in the import path: when a located book isUserBook && totalLines == 0 && is textual external, compute its line count with the reader's own text source/splitting, cache per title for the run. Expose via the locator (add `filePath`/format to `LocatedUserLinkBook` or a separate `lineCountOf(title)` callback injected like `locateBook`, so tests can stub it).
- Alternative (only if measured cheaper and safe): persist the count in a NEW nullable column/metadata — requires schema migration → avoid unless necessary.
