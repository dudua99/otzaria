# Issue #4497 — PDF Talmud (Chullin): navigation search "ב." / "קיא:" lands on the wrong daf (sweep 26.11 part 3)
Type: bug. Checked on dev 4fe1973a4.

## Reporter (answered on GitHub)
Chullin PDF. In the "ניווט" pane typed "ב." → clicked the list entry → went to "נ."; searched "קיא", clicked "קיא:" → went to "קב". Still happens after updating.

## Evidence (file:line on dev)
- lib/pdf_book/view/pdf_outlines_screen.dart:41-55 `filterPdfOutline` — plain `contains` over normalized titles, results kept in outline order, no ranking.
- lib/search/utils/find_match_utils.dart:23-46 `normalizeFindText` — "." and ":" are not letters/digits, so they are dropped (a separator at most). "ב." becomes "ב" and matches EVERY title that contains the letter ב (יב., כב., לב., נב. …, and parent titles); "קיא." and "קיא:" become the same string, so the amud is lost.
- The first rows of the filtered list are therefore unrelated dafim; the reporter clicked one of them. Ranking helpers already exist and are used elsewhere: `findNormalizedTextMatchRank` (find_match_utils.dart:67).
- Introduced/kept by the outline search (perf rewrite cc32aa120, 2026-10-06, kept the contains semantics).

## Fix idea
In `filterPdfOutline`:
1. Rank: exact title first, then prefix, then contains (`findNormalizedTextMatchRank`), stable within a rank (outline order).
2. Amud: when the raw query ends with "." or ":" (or ׳ע״א/ע״ב is not needed), require that the raw title ends with the same mark after the daf letters — "ב." must not match "ב:" and "קיא:" must rank "קיא:" first. Use a small helper that extracts (daf letters, amud mark) from the raw title.
3. Whole-token for short Hebrew-numeral queries: "ב" should match the token "ב", not "נב". A token-boundary check (title token == query or starts with the query) is enough.

## Test (must fail on dev)
test/pdf_book/view/ (an existing outline filter test from cc32aa120 — find it with `grep -rn filterPdfOutline test`). Outline titles: ["ב.", "ב:", "יב.", "נ.", "נב.", "קב.", "קיא.", "קיא:"]. Query "ב." → first entry "ב." and no "נב."/"יב."; query "קיא:" → first entry "קיא:" and "קיא." not before it.

## Pitfalls
- The second symptom (clicking the "קיא:" row went to "קב") may also be a wrong bookmark destination inside the Chullin PDF (data). After the filter fix, if a row still opens the wrong page, check `node.dest.pageNumber` for that row; if the bookmark itself points to the wrong page, that part is DATA (the PDF in the library) — say so in the PR, do not patch it in code.
- Do not change `normalizeFindText` globally (used by the text-book itur and other panes).
