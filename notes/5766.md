# Issue #5766 — feature-default notes (verify everything)
Type: FEATURE (suggestion, from-app, Windows 0.9.98.3, report e341219b). Assignee: none. Maintainer stance: none (no comments). No open PR. Reporter: while a library search runs and the user switches to another book tab, the search tab's label should show whether it is still searching or finished, so they don't keep switching back to check.
Constraint: no new layout in the tab strip; reuse the existing leading icon slot of a search tab.

## Requested behavior / DEFAULT
DEFAULT: in every place that shows the search tab's leading icon (top tab strip, vertical tab column, tab-search menu), while the tab's search is running (`SearchState.isLoading || isCounting`, and the semantic search equivalent) the search icon is replaced by `LoadingIndicator.inline()` at the same size; when it ends the icon returns. Tooltip of the tab: "מחפש…" while running; after it ends, the normal title (optionally "N תוצאות" if trivially available from state.totalResults — decide by lean code). Shown on every search tab (active or not) — cheap and consistent.
Acceptance:
- Widget test: SearchingTab with a searchBloc emitting isLoading=true → tab strip leading shows the loading indicator, not `OtzariaIcons.search_24_regular`; emit isLoading=false, isCounting=false → icon back (fails on dev: always the icon).
- Same for the vertical strip (`buildTabTypeIcon`).
- Narrow tab where the icon is hidden (custom_title_bar.dart L1370 condition) still shows the search tab's leading (search tabs show it whenever `leadingIconFits`) — the spinner follows the same rule.
- Text/PDF tabs unchanged; no rebuild storm: listen with BlocSelector/StreamBuilder on the tab's own searchBloc only.

## Implementation sketch
- One widget `SearchTabLeading(tab, size, color)` in tab_visuals.dart: BlocBuilder on `tab.searchBloc` with `buildWhen` on the running flag → spinner or the icon. Use it from the three call sites instead of the raw icon for SearchingTab.
- Lean: no new state, no timers.
