## Requested behavior
A personal book (Word/TXT in a custom folder) that is open in the reader doesn't pick up edits made to its source file, even after "refresh personal books" in settings; the user must close and reopen it.
Default spec (mmichaelush): F5 in the reader of a PERSONAL book re-scans that book's file and reloads the open tab in place.
Acceptance:
- F5 while a personal text book tab is focused: rescans only that book's folder (`RescanCustomFolders(onlyFolderPath:…, showNoChangesMessage:false, requestId:…)`), waits for completion, then reloads the tab content keeping the reading position (same line index if still in range, else nearest heading).
- UiSnack (catalog message) "הספר רוענן" / "אין שינויים בספר" / error message — never e.toString().
- F5 on a non-personal book: no-op (or same message "ריענון זמין לספרים אישיים בלבד" — pick no-op to avoid noise).
- The shortcut is configurable like other reader shortcuts (key `key-shortcut-refresh-book`, default 'f5') and listed in the shortcuts settings.
- Also: after a manual "refresh personal books" in settings, already-open personal tabs whose file changed are reloaded (the reporter's main complaint) — include if cheap: listen to `CustomFoldersState.completedScan` and dispatch reload to affected open tabs.
