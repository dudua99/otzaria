# Issue #5904 — bug notes (verify everything)
Type: BUG (labelled bug; milestone 0.9.99, from-app, Windows 11, 0.9.98+99803). Assignee: none. No open PR. No comments.
Reporter: select a segment, then page with the on-screen segment arrows: the RIGHT arrow clears the selection, the LEFT arrow keeps it.

## Evidence (upstream/dev @c400e543f) — reproduce first
- Buttons: lib/widgets/navigation/reader_nav_center.dart L113-184. Minor chevrons (`chevron_left` prevMinor, `chevron_right` nextMinor) have no `flipInRtl`; in the RTL layout the right-hand arrow = "הקטע הקודם" (previous), left-hand = "הקטע הבא" (next). Keyboard arrows map the same way (combined_book_screen.dart ~L2050-2075).
- Both go to text_book_screen.dart `_scrollByLines(state, ±1)` L1965-1992: `UpdateSelectedIndex(target)` then `lines.scrollToLine(target, alignment: 0, 300ms)`.
- Asymmetry: lib/text_book/view/combined_view/combined_book_screen.dart `_onScroll` L1335-1352 (listener on `lines.position`, L945; split view only): if `selectedIndex` is not in `state.visibleIndices` → `UpdateSelectedIndex(null)`. `visibleIndices` is debounced/throttled in text_book_bloc.dart L97-103. Next: target = top+1 is already visible → kept. Previous: target = top-1 is above the viewport, the first scroll ticks fire while visibleIndices is stale → selection cleared.
- Suspected root cause: 9c79c5f14 (13.11, "מעבר לקטע הבא או הקודם בוחר אותו (#3708)") added the select-on-navigate without accounting for the older `_onScroll` auto-clear (2a82cd9a0 or earlier).

## Fix direction
Suppress the auto-clear during programmatic navigation (e.g. a "navigation target" / epoch set in `_scrollByLines` and honoured in `_onScroll` until the scroll ends and visibleIndices include the target), or clear only on user-driven scroll. Do not remove the auto-clear for manual scrolling.
