# Issue #5745 — bug notes (verify everything)
Type: BUG (milestone 0.9.99, from-app, Windows 0.9.98.3). Assignee: none. Maintainer stance: none (no comments). No open PR on the link/mark path. Reporter: "העתק קישור עם הדגשת הטקסט" from שולחן ערוך while the commentator markers (ציוני המפרשים, the injected word-anchor letters) are SHOWN → opening the link shows the markers/links doubled and weird; if the link was copied while markers are HIDDEN the highlight "falls" (not applied), because the link text does not match the displayed text.
Constraint: no change to the link format (`&m=`) or to the copy/selection of plain text; only which text goes into `m=` and how it is matched.

## Requested behavior
A text-mark link highlights the same words whether the commentator markers are shown or hidden, when copying and when opening, and never duplicates/garbles the markers.
Acceptance (VERIFY ON DEV FIRST: 4a1dd70c8 (ypl, 15.11) switched the link text to the source selection; if all four cases pass on dev unchanged → NOT READY, report "fixed by 4a1dd70c8" with test evidence):
- Book with word-anchor commentator links (שולחן ערוך אורח חיים + משנה ברורה), markers SHOWN, select a range that contains an injected marker → copied link's `m=` (decoded) contains no marker letters (= source text).
- Open that link with markers SHOWN → the whole range highlighted once (`otzaria-mark` background), the marker still rendered once and still a link, no duplicated letters/links.
- Open the same link with markers HIDDEN → same words highlighted.
- Link copied with markers HIDDEN and opened with markers SHOWN → highlighted (range crosses a marker).
