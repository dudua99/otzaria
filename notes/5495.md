# Issue #5495 — feature notes (verify everything)
Type: FEATURE/behaviour decision (milestone 0.9.99; labelled bug). Assignee: none. Maintainer stance: none. NEEDS_DECISION.

## Requested behavior
Reporter opens a new window, then closes the FIRST (main) window, then the new one. Next launch restores only the books of the last-closed window; the main window's (many) books are gone.
Current design (verified in code, behaves as designed): closing a window discards its session (view_window_close_flow.dart ~L107-111: `rememberClosed` then `_discardSession(slot)`); the closed window is only reopenable in the same run via Ctrl+Shift+T (view_window_opener.dart `_ClosedWindow`, in-memory list, `rememberClosed` ~L500). Closing the main window while a view window is open hides it and drops its session; at exit only the surviving window's session remains → restored at next launch. This mirrors browsers (restore the last window).
Question for the owner: what should the next launch restore when windows were closed one after another?
 (a) keep current (last window only) — document it;
 (b) DEFAULT PROPOSAL: keep current restore, but persist the "recently closed windows" list (the Ctrl+Shift+T stack, max N) across restarts, so after launch Ctrl+Shift+T / a menu item "פתח מחדש חלון שנסגר" brings back the main window's tabs;
 (c) treat closing the main window while others are open as "minimise to background" and restore all windows' sessions at next launch.
Acceptance for (b):
- Closing window A then window B (exit); relaunch shows B; Ctrl+Shift+T reopens A with its tabs and bounds.
- The persisted stack is capped (same cap as now — the 'כמה חלונות סגורים נזכרים לשחזור' constant ~L74) and cleared of entries whose books no longer exist (handled by loadTabs skipping missing books).
- A single-window user sees no change.

## Where in the code
- lib/core/windowing/multiview/view_window_opener.dart (`_ClosedWindow`, `_push`, `rememberClosed`, reopen path; slots reserved for restore ~L97, L265-270 "שחזר את כל החלונות").
- lib/core/windowing/multiview/view_window_close_flow.dart (close order: flush → rememberClosed → discard).
- lib/core/user_state/window_session_store.dart (`window_sessions` table; L24-28: a row left after close means crash → restored).
- Main-window hide path: search `_ClosedWindow.main()` usages in view_window_opener.dart / main_window_screen.dart.

## Implementation sketch (b)
- Persist closed sessions in a separate table/kv (`closed_window_sessions`, JSON of WindowSession) in the same user-state DB, written in `rememberClosed` before discard; load into the stack at startup.
- For the main window's hide, capture its session the same way before it is dropped.
