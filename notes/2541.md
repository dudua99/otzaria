# Issue #2541 — feature notes (verify everything)
Type: FEATURE (milestone 0.9.99). Assignee: none. Maintainer stance: Y-PLONI 03.11 diagnosis: "לשמור לכל bookId את הפריט האחרון שנצפה, ולשחזר אליו אחרי טעינת הנתונים; בספר היררכי לוודא שהמקטע המכיל אותו פתוח ... פריט שכבר אינו קיים צריך לחזור לברירת מחדל תקינה".

## Requested behavior
Opening a book in שמור וזכור always starts at the top (דף ב). It should open where the user is holding.
Acceptance:
- Per book (bookId; fallback key category+name like `_getProgress` does), remember the last item the user touched (checkbox toggled on/off or row tapped) — "last V in time", NOT the highest marked index (Y-PLONI: highest index ≠ last V).
- On opening the book detail screen, after data loads: expand the ancestor sections of that item and scroll it into view (near the top, with the header row still visible).
- Survives closing the tool and app restart (persisted with the progress data).
- If the stored item no longer exists (TOC changed, index ≥ total) → open at top, no error.
- Two books keep independent positions.

## Implementation sketch
- Provider: `int? lastTouchedIndex(bookKey)` + `setLastTouched(bookKey, index)` persisted next to completion dates (same file/prefs mechanism; additive key → no migration).
- Call setLastTouched from the checkbox/range-mark handlers (single choke point in the screen or provider `updateProgress`).
- Screen: add a ScrollController; post-frame after details load: expand ancestors (sections whose leaf list contains the index), then `Scrollable.ensureVisible` on a GlobalKey attached only to that row (rows are built lazily — jump to an estimated offset first (index × row extent) then ensureVisible in the next frame).
- Respect reduced motion (DD-21): jump, don't animate, on open.
