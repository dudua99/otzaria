## Requested behavior
Index size doesn't shrink after removing books from the folder; re-adding them grows the index again (old data not reclaimed).
Acceptance:
- Step 1 (mandatory, per palmoni5): a measured scenario test/log — add N personal books → index → remove → refresh → re-add → index; record live doc count and on-disk size after each step, after commit, after optimize. Put numbers in the PR.
- Step 2: when an orphan cleanup removes a significant amount (threshold, e.g. ≥ 50 books OR ≥ 2% of indexed books — tune from step 1), schedule a best-effort compaction (`optimizeIndexBestEffort(index.optimize)`) in the background when no indexing/search-heavy work is running, not on the startup path.
- Same for the re-index path that replaces existing books (`replacing` already compacts at ~L1097 — verify it covers re-add of previously removed books; if re-add is treated as new, ensure deleted docs are merged away).
- Intentionally preserved sources (unreachable drive, hidden folders) remain untouched.
- No change when nothing was removed.

## Where in the code
- lib/indexing/repository/indexing_repository.dart `dropOrphanedIndexEntries` (~L2583-2687): `compact` param; optimize only when `compact && !indexPdfBooks()` (comment: "תחזוקה מפורשת בלבד: ניקוי היתומים בעלייה אינו מבקש איחוד כבד"); `optimizeIndexBestEffort` ~L2250; indexing-run compaction ~L1097-1117 (`compact = wholeLibrary || replacing`).
- Callers: lib/navigation/utils/refresh_indexing_plan.dart L122 (mode change, no compact), L135 (PDF off, compact:true); lib/navigation/view/main_window_screen.dart:3220 (refresh, no compact).
- Engine (separate repo otzaria_search_engine): commit vs merge/GC (search_engine.rs ~L9841, ~L10261-10325) — do not change engine here.

## Implementation sketch
- Return removed count (already) → caller decides: if count ≥ threshold, enqueue a deferred `CompactIndex` event in IndexingBloc that waits for idle (no active indexing, app not in startup reveal) and runs optimize; respect the existing `!indexPdfBooks()` guard reason (find why PDF disables optimize — likely cost; if so, keep it or make threshold stricter).
- Log result to errors.txt-style diagnostics like other indexing runs (size before/after).
