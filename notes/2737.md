# Issue #2737 — feature notes (verify everything)
Type: FEATURE (milestone 0.9.99; labelled bug). Assignee: none. Maintainer stance: Y-PLONI 03.11 diagnosis + plan: "להוסיף למעקב יחידות משנה תחת הפרקים לפי line.heRef, בשני מסלולי הטעינה. נדרשת גם המרת הסימונים הקיימים: הם נשמרים לפי מיקום ברשימה".

## Requested behavior
In שמור וזכור, Mishna tractates are tracked per chapter only; users want one row per mishna.
Acceptance (Y-PLONI's verification list):
- Mishna books (e.g. "משנה ברכות", also שבת/אבות/תמיד — any tractate whose TOC chapters have no children but whose lines carry mishna heRefs) show chapters as expandable parents with one learnable row per mishna (Berakhot ch.1 = 5 rows).
- Marking a single mishna and marking a whole chapter (parent row / range dialog) both work.
- Existing progress is preserved: a chapter that was marked before the change becomes all its mishnayot marked, per column; completion dates kept; other books' indices untouched.
- Works in both load paths: provider (`shamor_zachor_data_provider.dart` `_buildSectionsFromToc` ~L428) and the isolate bootstrap (`shamor_zachor_bootstrap_worker.dart` ~L201-219).

## Where in the code
- Units: lib/tools/shamor_zachor/models/book_model.dart `_buildLearnableItemsFromSections` (~L227-262) — one LearnableItem per leaf section, `absoluteIndex` sequential.
- Progress keyed by absoluteIndex string: shamor_zachor_progress_provider.dart ~L200-207 (`_progressById[bookId][index]`).
- TOC query: bootstrap worker ~L201 (tocEntry JOIN tocText); line refs: `line.heRef` in the DB (check column name in lib/migration/models / database_library_provider).

## Implementation sketch
1. Detection (data-driven, not by name list): for a leaf TOC section spanning lines [start,end), query distinct heRef "mishna" boundaries within the range; if ≥2, synthesize child sections (id = `${section.id}#m${k}`, title = Hebrew numeral of the mishna, startPage = first line).
2. Index migration: persist a per-book `unitScheme` version. On first load with the new scheme, map old index i (old leaf L) → all new indices under L, copying PageProgress; write once; keep a backup of the old map (same storage) to allow rollback.
3. Keep both load paths using one shared builder function (avoid drift).
4. Performance: the extra query runs only for books being tracked; cache in `_tocCache`.
