## Requested behavior / DEFAULT
DEFAULT: when the title "שם הספר, כותרת1, כותרת2, …, כותרת עמוקה" does not fit, truncate from the START, not the end: the deepest (current) heading always stays visible; the book name collapses first, then the upper headings, shown as a leading "…," (e.g. "…, פרק כ, סעיף יג"). The full title is in the tooltip (already exists when truncated). If even the deepest heading alone does not fit, show it with end-ellipsis (single Text, as today's fallback).

## Implementation sketch
- Split `displayText` into segments on ', ' (name prefix + heading levels). Find the longest SUFFIX of segments that fits with a leading "…, " (measure with textScaler); render "…, " + suffix as one Text (maxLines 1). Keep the current split path when the whole location fits; keep the single-Text fallback when even the last segment doesn't fit.
- Small pure function (e.g. `startTruncatedTitle(segments, fits)`) so it can be unit-tested; no new widget library.
- Tooltip condition: anything hidden (prefix dropped or ellipsized).
